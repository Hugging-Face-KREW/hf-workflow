# L02. 피드백을 자세히 쓰면 수정이 더 잘되는가

**이 한 사례에서는 간결한 지적만 준 조건으로 충분했습니다. 설명을 길게 덧붙인 조건은 문장의 의미를 누락했는데도 검사를 통과했습니다.**

### 기준선과 실험 조건

L01과 같은 `dataset card` 문장 1개를 네 조건으로 수정했습니다. 생성과 별도 모델 검토에는 gpt-5-mini-2025-08-07을 사용했습니다. F1과 F2의 오류 정보는 같고, F2에 설명 문단만 추가했습니다.

| 조건 | 모델에 준 정보 | 실제 출력 | 자동 검사 |
|---|---|---|---|
| 기준선 F0 | 원문·기존 번역, 오류 지적 없음 | 영어 dataset card를 그대로 둠 | 거부 |
| F1 | 기준선 + 구조화한 오류 지적 | 링크 설명을 번역하고 나머지 문장 유지 | 수락 |
| F2 | F1 + 지적을 읽는 방법을 길게 설명 | 번역한 링크만 남기고 문장 나머지 삭제 | 수락했지만 잘못된 수락 |
| F3 | F1 + 앞뒤 문맥 | 링크 설명을 번역하고 나머지 문장 유지 | 수락 |

### 기준선보다 나아졌나

F1과 F3은 기준선이 남긴 영어 설명을 고쳤습니다. F2도 링크 설명은 번역했지만, 원문의 ‘각 결과의 정확한 의미를 설명한다’는 내용을 지웠으므로 좋은 수정으로 볼 수 없습니다. 자동 수락 3건을 수정 성공 3건으로 집계하면 안 됩니다.

이 자료만으로 긴 피드백이 항상 나쁘다고 결론낼 수는 없습니다. 다만 자세한 지시 자체가 의미 보존을 보장하지 않으며, 직접 검사와 Guardrails가 같은 누락을 함께 놓칠 수 있다는 회귀 사례입니다.
