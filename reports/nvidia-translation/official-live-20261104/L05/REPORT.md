# L05. Guardrails의 기본 검사와 번역 전용 검사는 무엇을 놓치는가

**번역용 오류 기준을 명시한 검사가 일반 검사보다 오류를 덜 놓쳤습니다. 하지만 검사 둘을 연결한 조건이 더 좋지는 않았고, 수정 후 승인에서도 잘못된 결과가 남았습니다.**

### 기준선과 실험 조건

이미 개발에 사용한 후보 39개를 검사했습니다. 개발용 표시상 오류 후보는 25개, 정상 후보는 14개입니다. 모든 조건의 판정 모델은 gpt-5-mini-2025-08-07입니다.

| 조건 | 무엇을 검사했나 | 오류 후보 25개 중 잘못 통과시킨 수 | 정상 후보 14개 중 잘못 막은 수 |
|---|---|---:|---:|
| 기준선: 일반 직접 검사 | 일반 번역 평가 프롬프트를 Python에서 호출 | 16 | 0 |
| Guardrails 사실성 검사 | 번역이 원문에 근거하는지 내장 facts 검사로 확인 | 19 | 0 |
| Guardrails 번역 전용 검사 | 미번역·누락·용어·문법 등을 명시한 output 검사 | 4 | 0 |
| Guardrails 사실성 + 번역 검사 | 사실성 검사 후 번역 검사 | 8 | 0 |
| 같은 프롬프트의 직접 검사 | 직전 조건과 같은 프롬프트를 Python에서 실행 | 6 | 0 |

각 조건은 별도 모델 호출입니다. 같은 프롬프트라도 응답이 달라질 수 있으므로 마지막 두 행의 차이를 프레임워크 성능 차이로 보지 않습니다. 표시된 오류/정상은 개발용 기준이며 사람 정답이 아닙니다. 재사용 합성 후보 16개와 이전 회귀 후보 23개가 섞여 있습니다.

### 수정까지 해 보면 어떤가

합성 후보 16개에서 검사에 걸리면 한 번 고친 뒤 다시 검사했습니다.

| 조건 | 처음 검사에 걸려 수정한 후보 | 최종 승인 수 | 승인됐지만 고정된 의미·용어 조건을 위반한 수 |
|---|---:|---:|---:|
| 기준선: 일반 직접 검사 | 5/16 | 16/16 | 3 |
| Guardrails 사실성 + 번역 검사 | 7/16 | 16/16 | 1 |
| 같은 프롬프트의 직접 검사 | 7/16 | 16/16 | 1 |

### 기준선보다 나아졌나

번역 전용 검사는 기준선보다 오류 통과가 16→4건으로 줄었습니다. 수정 루프도 일반 검사보다 잘못 승인한 결과가 적었습니다. 그러나 모든 조건이 최종 16개를 전부 승인했는데도 실제 고정 조건 위반은 남았습니다. 자동 승인 횟수를 수정 성공률로 사용하면 안 됩니다.

번역용 검사 기준은 후속 비교에 남길 가치가 있습니다. Guardrails 도입 자체의 품질 우위는 확인하지 못했으며, 의미·코드·URL의 독립 검사를 함께 통과하기 전 자동 반영은 보류합니다.

잘못 통과는 오류로 표시한 입력에서 passed=true인 검사 수이며, 잘못 차단은 정상으로 표시한 입력에서 passed=false인 검사 수입니다. 수정 수는 repair_attempted=true인 행, 승인 후 위반은 approved=true이면서 invariant_ok=false인 행을 셉니다. 의미·용어 조건은 입력별 require_any의 각 묶음에서 하나 이상이 존재하고 forbid의 문자열은 없는지 확인하는 규칙입니다. 공개 파일의 candidate와 규칙으로 이를 다시 계산할 수 있습니다. 원본ID·파일명·해시를 보존했고 원자료는 수정하지 않았습니다.
